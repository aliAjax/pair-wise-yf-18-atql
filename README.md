# hxyfront-62006 珠宝镶嵌派工账本

源提示词编号：8（在原"宝石分拣"基础上，把分拣页改造为派工账本）

镶嵌车间每天按班组派石，复核结论与保险额度常在派工后变化。本系统把分拣页变成一本
**派工账本**，所有看板数字均由账本事实派生，不再依赖会失真的白板占位。

## 业务规则

- 每颗裸石**先占用订单石位**，再按班组工位容量放入当班队列；工位不足时按候补顺序
  （全局发号，先到先排）排队，仍放不下时在班组与顶部显示**最早阻塞项**。
- 派工即生成账本占用与**待确认回执**；写入失败保留回执，重试只重放写入，
  **绝不重复占用**石位 / 工位（每条派工有幂等键 `idemKey`）。
- 复核结论变化后**连带重算**相关订单：不再合格的石头退回原批次、释放工位，
  各班组候补自动顺延；若该派工写入尚未确认，对应回执作废。
- 保险额度变化同样留痕，但不改变派工。
- 每次变动保留**前后值、操作人、批次号、写入尝试次数**，可按订单 / 班组 / 状态 /
  关键词查看。
- 页面重载后，凭 localStorage 发件箱（outbox）幂等恢复待确认派工。

## 架构：规则、存档、页面分开维护

```
src/
├─ types.ts                 领域模型与枚举（三层共用）
├─ seed.ts                  演示数据（经规则引擎生成，保证初始看板自洽）
├─ engine/
│  ├─ rules.ts              规则引擎：纯函数，无 React / 无 localStorage
│  ├─ archive.ts            存档：localStorage 主账本 + 发件箱、模拟写入传输
│  ├─ store.ts             粘合层：调规则 → 落盘 → 走传输 → 回填结果
│  └─ lookups.ts            页面查询辅助
├─ components/              页面（派工 / 班组队列 / 订单石位 / 裸石台账 / 回执 / 留痕）
└─ App.tsx                  导航与全局筛选（按订单、班组、状态）
scripts/verify-rules.ts     规则引擎场景化自检
```

- 改规则只动 `engine/rules.ts`；改存储只动 `engine/archive.ts`；改展示只动 `components/`。
- 顶部"写入链路"可切换：正常 / 首次必败（抖动）/ 终端离线，用于演示失败与重试。

## 技术栈

React 19 + Vite 7 + TypeScript（严格模式）

## 本地运行

```bash
npm install
npm run dev          # 开发服务器 http://localhost:62006
npm run verify       # 规则引擎场景自检（占用 / 候补 / 幂等重试 / 连带重算 / 崩溃恢复）
npm run typecheck    # 类型检查
npm run build        # 生产构建
```

开发端口：62006
